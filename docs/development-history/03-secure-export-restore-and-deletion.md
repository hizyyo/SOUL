# Secure Export, Restore, and Deletion

**Дата:** 2026-07-31

## Цель

Позволить создать, изучить, безопасно экспортировать, восстановить и удалить пустой или заполненный локальный SOUL. Экспорт — зашифрованный пакет `.soul`, который импортируется обратно в новое локальное хранилище после проверки подписи, hash и схемы.

## Реализовано

- **Крипто-модуль `crypto.rs`**: ключи устройства Ed25519 (создание при первом экспорте, файлы `keys/device_ed25519.{secret,pub}`, на Unix — права 0600), шифрование XChaCha20-Poly1305 с ключом из пароля через Argon2id (параметры по OWASP: 19 MiB, t=2, p=1), подпись/проверка Ed25519, лимиты чтения файлов.
- **Пакет `.soul`** (`package.rs`): единый JSON-конверт (`format=soul-package`, `formatVersion=0.1.0`, `schemaVersion=0.1.0`) с открытым manifest (camelCase, `deny_unknown_fields`) и зашифрованным payload (`soul-export` v1: soul, entities, events, calibration). Подпись покрывает sha256 канонического manifest + шифротекст — любое изменение файла детектируется.
- **Экспорт**: `export_soul_cmd` (шифрованный `.soul`), `export_soul_json_cmd` (человекочитаемый JSON), `export_soul_markdown_cmd` (сводка по типам сущностей). Квитанции с путём, количеством сущностей/событий, hash и подписью.
- **Импорт/восстановление**: `inspect_soul_file_cmd` (полная проверка в памяти: размер ≤ 100 МБ, JSON, формат, версии, подпись, hash содержимого, пароль, цепочка событий, валидность JSON сущностей) → preview → `import_soul_file_cmd` (повторная проверка, затем wipe + вставка в одной транзакции).
- **Удаление**: `delete_soul_cmd` — `PRAGMA secure_delete` + DELETE всех таблиц + `wal_checkpoint(TRUNCATE)` + `VACUUM` (содержимое физически удаляется из файла), удаление ключей устройства, локальная квитанция `receipts/deletion-*.json` без личного содержимого.
- **UI (Settings)**: статус SOUL (ID, версии, head hash, счётчики), бэкап с паролем (ввод дважды), экспорт JSON/Markdown через нативные диалоги (tauri-plugin-dialog), мастер восстановления (выбор файла → пароль → preview с предупреждением о замене → подтверждение), опасная зона удаления с подтверждением `DELETE`, экран квитанции об удалении.
- **Интеграция**: плагин dialog (Cargo + npm + capabilities), новые команды зарегистрированы в invoke handler.

## Проверка безопасности

- **Угрозы**: подделанный/повреждённый/неподписанный пакет, неверный пароль, инъекция данных через пакет, exec-содержимое, утечка секретов в логи, восстановление поверх чужих данных, остатки удалённого содержимого.
- **Меры**: подпись Ed25519 поверх канонического manifest + шифротекст; Argon2id против brute-force; `deny_unknown_fields`; проверки длины salt/nonce/ключей/подписи; лимит размера 100 МБ; payload валидируется до любых изменений БД; импорт только через подтверждённый preview; импорт не выполняет код (чистый JSON); удаление с secure_delete + VACUUM; квитанции без личного содержимого; пароли не логируются и не хранятся (только в IPC).
- **Ограничение (честно)**: аутентичность ключа устройства — самоподпись в P0 (первый ключ становится корнем доверия — P1); ключи лежат файлами с ограниченными правами (OS keychain — P1); удаление не гарантирует физического стирания SSD-блоков.

## Влияние на производительность и токены

- Экспорт/импорт — не горячий путь, LLM не вызывается: 0 токенов.
- Argon2id ~200-300 мс на экспорт/импорт (тесты используют лёгкие параметры: ~10 мс).
- Ограничение: чтение/запись всего содержимого в память (≤ 100 МБ).

## Известные ограничения

- Один SOUL на устройство (P0): восстановление заменяет текущие данные после подтверждения preview.
- Ключ устройства в файлах, а не в keychain.
- Экспортные пароли не хранятся — забытый пароль = невосстановимый бэкап.
- Нет удаления отдельных сущностей (запланировано в SESSION-06 вместе с редактированием кандидатов).
