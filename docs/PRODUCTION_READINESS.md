# Готовность к production: разбор пробелов и дорожная карта

> Честная позиция: текущий продукт — **инвестируемый прототип** (ультра-MVP, сессии 00–13), не production-релиз. Спека (SOUL_ULTRA_MVP_CONTEXT.md) прямо запрещает продакшен-запуск и биллинг до прохождения kill criteria, внешней проверки P0 и явного решения основателя (§2.3, строка 191; SESSION-15, строка 1909). Этот документ — карта того, что отделяет прототип от production, по слоям, с гейтами и приоритетами.

## 1. Что уже на уровне продакшена (не нужно переделывать)

- **Локальные данные**: SQLCipher (шифрование на диске), ключ от device keypair, атомарный импорт/экспорт с подписью ed25519, капы KDF и лимиты размера (SESSION-03, SESSION-13).
- **Целостность**: capability и квитанции подписаны устройством, проверка подписи fail-closed, атомарное выполнение, повторная оценка политики, защита сохранённой нагрузки (SESSION-12 ultra-review).
- **Изоляция**: проверка владельца записи (soul_id) для сущностей/оценок, trusted-sender в браузерном relay, query_only для bridge/MCP, лимиты IPC, строгий CSP, отказ от shell-плагина (SESSION-12, SESSION-13).
- **Инженерия**: 222 Rust + 235 TS тестов, clippy/fmt/typecheck/lint чисто, аудит зависимостей 0 уязвимостей, детерминированные property-тесты политик и gateway.

## 3. Дорожная карта по фазам

### Фаза 0 — Валидация (гейт для всего P1)
Blind Preference Test (SESSION-10), удержание, готовность платить, kill criteria (§2.3, строка 191). **Без прохождения — ни биллинга, ни продакшен-запуска** (строка 194). При провале — pivot или остановка, а не «доделывание в стол».

### Фаза 1 — P0 до релизного качества (можно и нужно делать до гейта)
- **SESSION-14**: производительность, токены, надёжность (кеши, отмена запросов, перф-тесты, лимиты контекста).
- **SESSION-16**: полировка, demo-режим, инвесторский сценарий, a11y, безопасные ошибки.
- **SESSION-17**: подписанные сборки, обновления и откат, приватность, диагностика, SBOM, release checklist.

### Фаза 2 — P1 после гейта основателя
- **SESSION-15**: биллинг и доступ к функциям.
- **Настоящий Gateway**: изоляция учётных данных, реальные коннекторы, серверная верификация (§4.11, строка 1111).
- Ключи в OS keychain, корень доверия, облачная синхронизация, аккаунты.

### Фаза 3 — Масштаб
CI/CD на производстве, телеметрия, поддержка пользователей, инцидент-реакция, performance-бюджеты на уровне продукта.

## 4. Чек-лист релиза (база — приёмка SESSION-17)

- [ ] Чистая установка работает; обновление работает; путь отката задокументирован
- [ ] Выпуск не содержит секретов или личных тестовых данных
- [ ] Ограничения безопасности видимы пользователю; production-заявление ограничено реализованным поведением P0
- [ ] Полные наборы тестов, безопасности и производительности зелёные на релизной сборке
- [ ] Сборка подписана, SBOM и лицензии проверены
- [ ] Политика приватности опубликована; диагностика маскирует личное; сбои только по согласию
- [ ] Инструкции резервного копирования/экспорта доступны
- [ ] Демонстрационный поток (SESSION-16) проходит без основателя

## 5. Что сознательно не входит

- Универсальная «платформа агентов» — спека требует **узкий** production-выпуск (SESSION-17).
- Безлимитное тяжёлое рассуждение, продажа данных, реклама P0-имитации как защиты production-уровня.
- Мобильные приложения/веб-версия без отдельного решения и валидации.

## 6. Итог

Продакшен — это не одна сессия, а фаза 1 (3 сессии качества/релиза) + явный гейт валидации + фаза 2 (биллинг и настоящий Gateway). Ближайший шаг по спеке, не требующий гейта: **SESSION-14** (производительность, токены, надёжность).
